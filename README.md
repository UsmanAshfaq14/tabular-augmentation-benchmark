# When Does Synthetic Augmentation Help Tabular Learning?

Code for a multi-scale benchmark of synthetic data augmentation on tabular data,
carried out at IRIT (Université Toulouse Capitole) under the supervision of
Moncef Garouani and Julien Aligon.

Each configuration is judged on four measures, not on accuracy alone:

1. **Predictive performance**: R², RMSE, MAE and rare-region RMSE (regression); macro-F1, ROC-AUC and MCC (classification)
2. **Distributional fidelity**: Kolmogorov–Smirnov gaps and the Frobenius distance between correlation matrices (CorrFrob)
3. **Explanation stability**: Spearman rank correlation between SHAP feature importances with and without augmentation
4. **Cost**: wall-clock generation time

A paper describing the study is in preparation.

## Design

| | |
|---|---|
| Datasets | 24 from PMLB: 12 regression, 12 classification, 4 per size tier |
| Tiers | small, medium, large |
| Methods | `baseline` (no augmentation), SMOGN (regression) / SMOTE-NC (classification), CTGAN, TVAE, ForestDiffusion, GReaT, DiCE |
| Learners | Random Forest and XGBoost, 100 trees, `random_state=42` |
| Seeds | 42, 123, 456, 789, 999 |
| Test split | 30 % (small), 20 % (medium, large) |

| Tier | Regression | Classification |
|---|---|---|
| small | `230_machine_cpu`, `560_bodyfat`, `547_no2`, `1028_SWD` | `heart_c`, `saheart`, `australian`, `german` |
| medium | `titanic`, `529_pollen`, `294_satellite_image`, `503_wind` | `flare`, `cmc`, `car`, `churn` |
| large | `225_puma8NH`, `197_cpu_act`, `537_houses`, `344_mv` | `mushroom`, `nursery`, `adult`, `connect_4` |

Naming note: the folder and key `tabddpm` holds the **ForestDiffusion** method
(Jolicoeur-Martineau et al.), not the neural TabDDPM model.

## Running

```bash
pip install -r Implementation/Classification/requirements.txt

cd Implementation
export PYTHONPATH=.          # the scripts import `utils` from Implementation/
                             # (PowerShell: $env:PYTHONPATH=".")

python Classification/clf_small.py
python Regression/reg_small.py
# GReaT has its own scripts; run one after the main script for that tier:
python Classification/great_medium.py
python Regression/reg_great_medium.py
```

Each script's header documents its datasets, split and options. Runs are
checkpointed per cell, so an interrupted run resumes without recomputing
finished cells. GReaT downloads GPT-2 from the Hugging Face Hub; set `HF_TOKEN`
in your environment to avoid rate limits (never commit a token).

## Outputs kept in the repository

`Implementation/outputs/<task>/<tier>/<dataset>/<method>/`

| File | Content |
|---|---|
| `metrics_{rf,xgb}_seed<k>.csv` | predictive metrics per seed |
| `distribution_metrics_seed<k>.csv` | KS and CorrFrob fidelity |
| `shap_stability_{rf,xgb}_seed<k>.csv` | SHAP rank stability against the baseline |
| `shap_importance_{rf,xgb}_seed<k>.csv` | mean absolute SHAP per feature |
| `residual_report_*` / `classification_report_*` | text reports per seed |
| `comparison/all_methods_*.csv`, `comparison/*.png` | per-dataset summaries |
| `experiment_config.json`, `run.log`, `great_run.log` | configuration and run logs |

Not included because of size, and regenerated by re-running the scripts:
augmented and synthetic training sets, train/test split files, raw SHAP arrays
(`.npy`), per-seed plots and the GReaT fine-tuning checkpoints.
